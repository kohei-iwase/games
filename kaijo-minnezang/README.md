# 海城のミンネザング — 3Dプレイアブルモック 0.7

ビルド不要・外部依存なしのWebGL 3Dゲーム。騎士名と数値は仮設定です。世界観・キャラクター・トーン・音楽の基準は [docs/setting.md](docs/setting.md) を参照。

## 0.7の変更点：戦略マップ

設計メモ（[docs/design.md](docs/design.md) の「2. 戦略パート」「4. 最初のステージ」）に沿って、戦略マップ → 接触 → 戦闘パート → 戦略マップ、の流れで遊べるようにしました。ルールは `strategy.mjs`（DOM非依存）、3D描画は `mapscene3d.mjs` と `render3d.mjs` の `renderMap`、画面の流れは `app.mjs` にあります。旧「ネフェリム連戦」の状態（`camp`）は戦略マップに置き換えました。

- **流れ**：プロローグ →「出撃」で戦略マップ（ポーズ状態で開始）→ 敵と接触すると進行が止まり、「〇〇が△△と接触」の演出のあと出撃準備 → 戦闘（観戦／サマリー／完全スキップ）→ 結果 →「海図へ戻る」で戦闘の結果を戦略に反映して戦略マップへ（ポーズ状態）。ネフェリム撃破で勝利、峰の灯が消える・ミラルカ辺境伯の戦闘不能・全滅で敗北のエピローグ。
- **戦略マップの操作**：Spaceか右下のボタンで進行／戦術ポーズ（ポーズ中に「戦術ポーズ」を表示。ポーズ中も指示できる）。艦隊をマップ上か左下の一覧（1・2キーでも）で選び、海面か左上の海図をクリックで移動指示。敵をクリックするとその位置へ向かう。「停止」と、進行の倍速（×1／×2／×4）ボタン。ドラッグで視点移動、ホイール・＋／−でズーム、⟲で全体図に戻る。
- **HUD**：上部にネフェリムと峰の灯の耐久バー（島が包囲されている間は点滅）と経過時間。左下に艦隊一覧（艦隊名、各艦の紋章と耐久、状態：待機／移動中／補給圏）。左上の海図は海域全体（島・浅瀬・小島・艦隊・敵・移動先）。左にログ。
- **3D表示**：海面、峰の灯（灯の明るさが島の耐久で変わる）、浅瀬、小島、自軍艦隊（艦を縮小した海城の群れ。ミラルカの艦隊は深紅、別働隊は青。選択中は金のリング、移動先に点線とリング）、ネフェリム（巨人）と眷属の群れ（小さく暗い三つ組）。座標は戦略マップの0.4倍で、中心が原点。
- **準備画面**：接触した艦隊の編成と耐久、敵の名前と残り耐久、格の札（ネフェリム＝格上、眷属＝同格）、陣形、スキルの順番（その艦隊の騎士のみ。別働隊はオリーヴェ〈不退の誓い〉だけ）、予測。陣形とスキル順は艦隊ごとに保存されます。ジョストを持つのはミラルカの艦隊だけで、別働隊は観戦でも完全オートです。
- **記録**：勝利時のみ、沈めた艦（−10）・峰の灯の損傷（−0.3/点）・5分を超えた時間（−1/10秒）・7戦目以降（−2/戦）を100点から引き、S85・A72・B58・Cで評価（仮）。所要時間と戦闘回数も保存します。
- **音楽**：戦略マップと準備は行進曲、戦闘はネフェリムならワルツ・眷属なら行進曲、ドラマと結果はドラマ曲。

## 0.6の変更点：短い戦闘パート

設計メモ（[docs/design.md](docs/design.md) の「3. 戦闘パート」）に沿って、「1つの戦場で3隻を操作する」遊び方を、準備 → 30秒の自動戦闘 → 結果、の連戦に置き換えました。（この段階では戦略マップはなく「ネフェリムとの連戦」だけでした。現在の流れは上の0.7を参照。）

- **流れ**：プロローグ → 準備画面 → 戦闘（①観戦 ②サマリー ③完全スキップ）→ 結果画面 →「次の戦闘へ」で準備画面に戻る。ネフェリム撃破で勝利のエピローグ、旗艦の戦闘不能で撤退のエピローグ。判定負けは「押し戻された」と表示して次の戦闘へ（ネフェリムの傷はそのまま。自軍の艦は戦闘ごとに全快する仮設定）。
- **準備画面**：艦隊（主力艦隊 ミラルカ・カナン卿・随伴艦の固定編成）、陣形（各個／単縦陣／単横陣／輪形陣）、スキルの順番（札をクリックした順に1番目・2番目…。初期値は縫い留め→ジョストで連携）、予測（与・被ダメージの幅、会心時の与ダメージ、優勢／五分／劣勢）。変更から110ms待って `predict()` を再計算します。
- **観戦**：3Dでオート進行。操作はジョストの射出入力（F／ボタン）だけ。上部に残り秒数と判定ゲージ（左が与ダメージ率、右が被ダメージ率）。Spaceで一時停止、「サマリーへ」でその時点から切り替え。
- **サマリー**：戦闘を20倍速で進め、`Battle.logs` を時刻つきで流します。カットインは飛ばし、ジョストの射出集中が来たら通常の速さに戻して入力を受け付けます。
- **完全スキップ**：メニューの「戦闘を完全にスキップ」をオンにすると、準備画面に「結果だけ見る」が出ます。`simulate()` でジョストを通常射出として即座に計算します。
- **ネフェリムの耐久**：`Battle` の `enemyMaxHp` で最大耐久を指定できます（この連戦では2250、`enemyHp` が開始時の残り）。開始時に半分以下なら第二形態から始まります。
- **記録**：ネフェリム撃破までの戦闘回数でS〜Cを付け（3戦以内S、4戦A、5戦B、以降C。撤退は—）、最高評価と戦闘回数を保存します。
- 従来の手動操作用UI（旗・助走点・集合・個別の移動指示・スキルの手動予約・海図クリックでの指示・島の灯のバー・自動ポーズ設定）は取り除きました。海図は見るだけです。島は `island:false` で無効です。

## 物語パート

立ち絵の会話（ADV）で物語を見せます。プロローグ、ネフェリムとの初接触（準備画面の前）、主力艦隊が戦闘後に初めて峰の灯で補給したときの幕間の3場面が、`dist/story/*.txt` の台本から再生されます。クリック／Space／Enterで進み、右上の「ログ」「スキップ」が使えます。話者は前に出て明るく、ほかの人は暗く小さくなり、感情は立ち絵の色味と動き（跳ねる・揺れる・身を引く等）で表します。
台本の書き方（背景・登場・退場・演出・効果音・間、感情と動き）は [docs/story-format.md](docs/story-format.md) を参照してください。再生済みの場面は戦略の状態（`Strategy.seen`）に記録し、「最初から」でリセットします（プロローグは起動時の1回のみ）。台本の読み込みは `dist/story.mjs`（DOM非依存）、会話画面は `dist/talk.mjs`、場面の差し込みは `app.mjs`、確認は `node tests/story.mjs` です。

## 0.5の変更点（従来の1戦場版。ルールの多くは現在も `battle.mjs` に残る）

- **ドラマパートの最小版**：出撃前のプロローグと、結果に応じて台詞が変わるエピローグ。オウガバトル風の「ドラマ → 戦闘 → ドラマ」の一巡を体験できます。
- **戦果報告と評価**：勝利時はS〜Cで評価します。評価には残存耐久、連携回数、会心（ジョスト射出の好タイミング）回数、撃破時間が反映されます。連携・被害・蓄血などの統計と、次の戦いへの助言を表示。最高評価をブラウザに保存します。
- **難易度**：現時点では「正騎士」の1つのみ（最初のステージ向けに、敵の体力750・威力×0.9・攻撃間隔×1.25）。`battle.mjs` の `DIFFICULTY` に追加すれば段階を増やせます。
- **第二形態の新攻撃〈血潮の墜落〉**：薙ぎ払いと交互に使用。足元の血が最も濃い艦を狙う円形の叩きつけで、円内の血域を吸い上げて回復します（1回につき最大体力の7%まで、第一形態には戻りません）。血を吸うほど狙われるため、血域の取り合いが生まれます。
- **守る島「峰の灯」**：ネフェリムは基本的に島（左端）を目指し、島のそばで「灯を襲う」と灯が毎秒4減ります（0で敗北、旗艦の戦闘不能でも敗北）。艦が行く手（島の向き±50°・距離160以内）を塞ぐか、〈不退の誓い〉中のオリーヴェがいると、その艦へ向かいます。拘束・攻撃予兆・後隙の間は灯を削りません。戦果報告に灯の残りと敗因（`lost`）を追加。
- **浅瀬**：海図の薄い円（3か所）。敵の中心が円内にいる間は移動速度×0.35（艦は影響なし）。ジョストの押し戻しで押し込めます。
- **キャンペーン層の分離**：`campaign.mjs` は `Battle.report()` の戦果だけを受け取り、台詞・助言・記録を扱います。戦闘内部の状態には触れません。

## 画面UI

スマホのアクションゲーム風の全画面HUD。戦場を画面いっぱいに表示し、操作類は重ねて配置しています。

- 上中央：ボスHP（遅れて減るダメージ表示つき）、失血ピップ、残り秒数と判定ゲージ。攻撃予兆中は技名と残り秒数の警告帯と、画面外周の赤いビネットを表示
- 左：戦況ログのトースト。左下に艦隊のロスター（HP・蓄血）
- 右下：観戦中は「一時停止」と「サマリーへ」。ジョストの射出集中では下中央にタイミング入力
- 音：Web Audio API で合成する効果音・環境音（海と風）・仮の音楽（出撃準備はホルンのマーチ、戦闘はワルツ〔第二形態で転調・加速〕、ドラマ・戦果はチェンバロと弦）。音声ファイルは使わない。最初のクリック／キー入力で鳴り始める
- 効果音：戦術ポーズ・戦闘終了の鐘、カットイン、杭の出現、ジョスト射出、被弾、旗艦の耐久が3割以下の鼓動、ボタン操作。メニューで音のオン／オフと音量を変更でき、ポーズ中とメニュー中は音楽を下げる
- 準備・結果・サマリーはカード型のモーダル（ドラマ画面と同じ金縁の様式）。
- カットイン：画面右上の騎士色の斜めパネル、閃光ライン、四芒星。三人とも立ち絵（`dist/art/` の miralka.png・kanaan.png・olive.png）を表示し、立ち絵のない騎士は紋章を表示。立ち絵は `app.mjs` の `PORTRAITS` に騎士IDと画像パスを登録すると追加できる
- 海図：左上。戦闘中は彼我の位置・血域・浅瀬・敵の攻撃範囲（見るだけ）、戦略マップでは海域全体（クリックで移動指示）
- 3Dの予兆：塗りの濃い扇形・円、破線の縁、発動までの進行を示す塗り、ひび割れ線
- 設定と遊び方は左上の☰メニューに格納
- 設定：視点、戦闘の完全スキップ、ジョスト入力の自動補助、カットイン短縮、音を、☰メニュー（準備画面の「設定・遊び方」からも開ける）で変更できます。設定は `config.mjs` がブラウザに保存。自動戦闘ではイベントポーズをしません（`pauseMode` はオートでない `Battle` 用に残してあります）
- スマホは横画面専用。縦向きでは横向きを促す画面を出して戦闘を停止。Androidは出撃時に全画面化して横向きでロック、ホーム画面に追加した場合もマニフェストで横向き固定（iOS Safariはロック不可のため案内画面で対応）

## 3D表示とカメラ

操作キャラは旗艦・ミラルカ辺境伯（主人公）で、カメラは辺境伯を追い、ジョスト（棺から撃ち出す十字架の杭）も辺境伯が行います。辺境伯が戦闘不能になると撤退（敗北）です。☰メニューの「視点」で、**後方視点**（既定。旗艦の後ろ上方から進行方向を見る）、**1人称視点**（旗艦の艦橋から見る）、**俯瞰**（従来の戦場全体）を切り替えられ、選択はブラウザに保存されます。旗艦視点のドラッグは見回し（後方は周回・高さ、1人称は左右・上下）、カメラの向きは旗艦の針路に滑らかに追従します。旗艦が戦闘不能の場合は生存艦を追います。

海城（城壁・尖塔・旗・杭発射機・巨槍・盾）、二本腕のネフェリム、血海の拘束杭を実際の3Dメッシュで表示。水面は波と血液濃度をシェーダー描画します。ドラッグで旋回と俯角変更、ホイール・ピンチ・＋／−でズーム、視点リセットで初期状態に戻ります。ドラッグ後のクリックを命令として誤認しないよう抑止し、海面とのレイ交差で、視点操作とクリックを区別します。

## 遊び方

1. プロローグのあと戦略マップが開きます。2つの艦隊（主力艦隊：ミラルカ辺境伯・カナン卿・随伴艦、別働隊：オリーヴェ・随伴艦2隻）を動かして、西の島「峰の灯」を守りながらネフェリムを撃破します。Spaceか右下のボタンで進行／戦術ポーズ。ポーズ中も指示できます。
2. 艦隊を選び（マップ上・左下の一覧・1／2キー）、海面か左上の海図をクリックで移動指示。浅瀬では敵が遅くなり（ネフェリム×0.35、眷属×0.7）、小島は通れません。峰の灯のそばにいる艦隊は、艦が毎秒2%ずつ回復します（補給）。
3. 敵と接触すると進行が止まり、出撃準備になります。陣形とスキルの順番を選び、予測の「与／被ダメージ」と優勢・五分・劣勢の見込みを見て決めます。札をクリックした順に1番目・2番目…、もう一度で外れます。縫い留め→ジョストの順だと連携〈杭と十字架の馬上槍試合〉。
4. 「出撃」で観戦（30秒）。艦とスキルは自動で動き、操作するのはジョストだけです。射出集中の合図で、金色の範囲にFキーまたはボタン（会心×1.5。押さなくても通常射出）。ジョストを持つのはミラルカ辺境伯の艦隊だけで、別働隊の戦闘は完全にオートです。Spaceで一時停止・再開。
5. 「サマリーで進める」（観戦中は「サマリーへ」）は高速表示、「結果だけ見る」（メニューで設定）は即座に結果です。後者はジョストを通常射出として計算します。
6. 時間切れまでに、与ダメージ率（敵の最大耐久に対する割合）が被ダメージ率（自軍の総耐久に対する割合）以上なら判定勝ち。敵の耐久を削り切れば撃破。判定負け・撤退の艦隊は押し戻され、判定勝ちなら敵が押し戻されます。耐久は戦闘後もそのまま持ち越し、沈んだ艦は戻りません（補給で回復）。「海図へ戻る」で戦略マップへ。
7. 勝利：ネフェリムの撃破。敗北：峰の灯が消える（ネフェリムは毎秒3、眷属は毎秒1.5で削る）、ミラルカ辺境伯が戦闘不能になる、艦隊が全滅する。

- **陣形**：単縦陣（速力＋15%）、単横陣（与ダメージ＋10%）、輪形陣（旗艦の被害−25%・速力−15%）。各個は効果なし。
- **カナン卿〈縫い留め〉**：足元に血域のある敵を10秒拘束。血海から杭が現れ、移動・旋回を封じます。腕の攻撃は止まりません。
- **ミラルカ辺境伯〈ジョスト〉**（旗艦・主人公）：助走で加速し、基礎威力＋速度加算。射出集中時にFまたはボタンを押し、金色の範囲なら1.5倍。命中で押し戻しますが、薙ぎ払い中は敵の耐性が優先します。
- **連携**：縫い留め→ジョストの順で使うと連携。拘束中にジョストが命中すると杭を破砕し、追加失血・血域拡大。
- **堅牢なるオリーヴェ〈不退の誓い〉**：別働隊の旗艦。範囲内の味方への被害を抑えます（戦闘内）。

ネフェリムは低速で移動し、腕の広範囲薙ぎ払い時は停止。予兆で範囲と向きを固定します。実行後3.5秒の後隙。離れた敵には威力控えめの遠距離攻撃。体力50%で第二形態となり、〈血潮の墜落〉を交互に使います。

血域は海面に残り、中心ほど濃く、24秒で薄れます。吸血で各海城に最大100を蓄え、25ごとに役割に応じた強化。定期ポーズはありません。

## 構成と検証

`dist/strategy.mjs`はDOM非依存の戦略マップのルール、`mapscene3d.mjs`は戦略マップの3Dモデル、`dist/battle.mjs`はDOM非依存の戦闘処理、`render3d.mjs`はWebGL描画とラベル・カメラ、`scene3d.mjs`は立体モデルと演出、`space3d.mjs`は座標変換と形状、`shaders3d.mjs`は照明・海面・血域、`app.mjs`は操作・HUD・演出時間管理、`campaign.mjs`はプロローグ・エピローグ・助言・記録保存と、連戦の結果（`battleVerdict`、`campaignReport`）。`app.mjs` は準備・観戦・サマリー・結果の流れを持ちます。カットイン中は戦闘時間停止。射出集中では戦闘速度0.12倍（サマリーは通常は20倍、射出集中だけ0.12倍）。

- `node tests/combat.mjs`：血域の濃度と残留、蓄血維持、ポーズ、同時発動、拘束、射出入力、ノックバック、連携、勝敗、難易度（1段階・不明な指定の補正）、〈血潮の墜落〉の標的・吸血、戦果報告と評価、`enemyMaxHp`（最大耐久の指定と開始時の残り耐久）を検証。
- `node tests/strategy.mjs`：戦略マップのルール（移動、小島、浅瀬、接触と戦闘の反映、補給、勝敗、自動プレイ）を検証。
- `node tests/story.mjs`：台本3本の読み込み（警告なし、命令の種類と件数）、名前の解決、感情から既定の動き、`／` の改行、心の声、半角 `[]`、未知の命令が警告になること。
- `node tests/campaign.mjs`：勝敗別のエピローグ、助言、記録保存（敗北で勝利記録を上書きしない、保存不可の環境でも動く）、設定の保存・読込・不正値の補正、連戦の結果と連戦記録（戦闘回数）を検証。
- `node tests/ui-smoke.mjs`（0.6の画面には未対応。旧UIのボタンを前提にしているため、更新が必要）：簡易DOM、WebGL呼び出しアダプターと実際のイベントハンドラーでカメラ・出撃、予約、カットイン、入力、集合、初期化を検証。
- `node tests/geometry3d.mjs`：324組のカメラ条件と海面座標の往復変換、全メッシュの有限値と、戦略マップのモデル（`buildMapScene`）の有限値・座標変換を検証。ネイティブ描画用シーンを一時領域へ出力。
- `python tests/native3d.py`：同じシェーダー・メッシュ・カメラでEGL/OpenGL ESによるオフスクリーン描画を実行し、シェーダーのコンパイル、リンク、GLエラー、白紙出力を検証。
- `tests/render.mjs` と `dist/render.mjs` は旧2D版の検証用。現在のゲームでは読み込みません。

ネイティブ3D描画結果の目視確認済み。ブラウザ実機での操作・レイアウト確認は未実施。カットインは騎士の紋章による仮演出。音声、キャラクター立ち絵、本格的なドラマパート（分岐・編成）はまだ含みません。


## ローカルで起動する

Python 3 がインストールされている環境で、リポジトリのルートから実行します。

```sh
python3 -m http.server 8000 --directory kaijo-minnezang/dist
```

ブラウザで http://localhost:8000 を開いてください。ES Modulesを使うため、HTMLファイルの直接オープンではなくHTTPサーバー経由で起動します。ビルドやnpm installは不要です。WebGL対応ブラウザが必要です。

戦闘ルールと3D座標変換のテストは、Node.jsで実行できます。

```sh
cd kaijo-minnezang
node tests/combat.mjs
node tests/campaign.mjs
node tests/geometry3d.mjs
node tests/strategy.mjs
```

UI・画像の検証は任意で、`@napi-rs/canvas`、PythonのPillow、LinuxのEGL/OpenGLなど追加の環境が必要です。これらはゲームを遊ぶためには不要です。
